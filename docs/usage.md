## 第一次使用

1. 打开面板（首次访问直接进，因为还没设密码；设了 `TOKEN` 就用它登录）
2. 「配置接口」→ 粘贴一个 TVBox 配置地址 → 添加
3. 点「立即重新聚合」，等 3~10 分钟
4. 「输出」里挑一个地址，填到电视上

> 聚合过程会真的去请求几十上百个采集站，慢是正常的。面板会显示进度。

## 配置接口

一栏"接口"就是一份 TVBox 配置（单仓 json 或多仓 json 都支持）。

| 操作 | 说明 |
|---|---|
| 添加 | 贴上地址即可，会自动判断是单仓还是多仓 |
| 设为主用 | 主用接口才会被完整解析（探活、合并站点） |
| 设为备选 | 备选**只做浅解析**：只数里面有多少站，不探活。每 2 天自动初筛一次 |
| 删除 | 删掉后它带进来的站点会标记为**离源**，继续参与聚合 |

**主用上限**默认 10 条。少了会自动从备选里补（按浅解析出的站点数排序），
补进来的接口下一轮才会被完整解析。

### 批量添加

点「批量添加（最多 10 个）」，一行一个地址贴进去。

- **一次最多 10 个**，超过 10 个只读前 10 个，结果里会写明「忽略了后面 N 个」
- 自动识别 `http://` / `https://` 开头，内网地址、重复地址会单独列出来跳过
- 加入后**立即在后台开始解析**，10 个跑完要几分钟，页面不会卡住

### 导出配置（txt）

点「导出配置 txt」，会下载一份可以直接用记事本打开的文件：

```
# TVBox 聚合器 · 配置导出
# 时间：2026-11-27 16:20:00 ｜ 版本：0.9
# 接口：64 个（主用 10 ｜ 备选 54）
#
# 接口行格式：档位<TAB>名称<TAB>地址（可直接手改，导入时按地址去重）

[接口]
主用	某接口	https://example.com/config.json
备选			https://example.com/other.json

[设置]
config_days=5
live_lines_per=5
```

导出内容：**接口 + 设置 + 站点屏蔽 + GitHub 镜像**。

```
[接口]
主用	某接口	https://example.com/config.json
备选			https://example.com/other.json

[设置]
config_days=5

[屏蔽名单]
名字	哔哩
资源	bilibili.com

[GitHub镜像]
https://gh-proxy.com/{url}
```

**不导出采集站、扩展站、直播源**，原因：

| 导出项 | 为什么 |
|---|---|
| 配置接口 | 是"根"，机器换掉后没它什么都恢复不了 |
| 设置项 | 手调过的参数，重建不了 |
| ~~采集站 / 扩展站 / 直播源~~ | **都能从接口重新拉取**；导出去再导回来只会和池子里现有的重复，反而制造冲突 |

换机器/重装时：装好 → 导入这个 txt → 等一轮聚合，站点和直播源就都回来了。

### 导入配置

点「导入配置」选那个 txt，会问一句「要不要同时覆盖设置」：

- **确定** = 接口和设置都导入
- **取消** = 只导接口，现有设置不动

导入是**合并**，不是覆盖，每一类都按自己的规则去重：

| 内容 | 导入方式 |
|---|---|
| 配置接口 | 按 URL 去重，已存在的跳过 |
| 设置项 | 只有你点了「确定」才覆盖 |
| 站点屏蔽 | 按关键字合并，忽略大小写去重，不会删你现有的 |
| GitHub 镜像 | 按地址合并去重，保留原有顺序 |

所以**反复导入同一个文件不会产生重复**——结果里会显示「跳过 N 个」「新增 0 条」。

**什么时候删掉一个接口**：连续 3 次拉不到会自动删。删之前它带进来的站点会转成离源。

## 采集站点

聚合的每一个站，都能在这里看到体检结果。

| 列 | 含义 |
|---|---|
| 央视/卫视 | 只有直播源才有的统计 |
| 状态 | 在线 / 暂留 / 摘除 |
| 可播 | 随机抽 20 条片子，实际能播的比例 |
| 耗时 | 响应时间 |
| 被使用 | 这个站出现在哪几档输出里 |

**数字怎么看**：

```
采集站点 39 ｜ 体检 39 → 去重 30（在线 30 ｜ 暂留 2 ｜ 摘除 7）｜ 主用 25 ｜ 合并重复 9
```

- `体检 39`：这一轮实际探了多少个
- `去重 30`：同一台机器被多个接口重复收录，合并后剩 30
- `合并重复 9`：被合并掉的重复数
- `主用 25`：真正进了输出的

**可搜索**是重要指标：假搜索的站会被排到最后，不占主站名额
（它们在客户端点搜索会返回一堆垃圾，体验很差）。

## 扩展站点与插件扫描

扩展站点是 `type=3` 的插件（jar/js/py）。面板会对每个插件做**静态扫描**：

| 判定 | 后果 | 触发条件 |
|---|---|---|
| 拦截 | 不进任何输出 | 装 APK、杀后台进程、执行外部命令、夹带 `.so`、压缩炸弹、jar 解不开 |
| 标注 | 正常输出，但标记出来 | 会起本地代理、会申请存储权限、会读设备标识 |
| 正常 | - | 以上都没有 |

**"会起本地代理"是什么**：插件会在本机起一个 HTTP 服务，把播放请求转发出去
（通常是为了补 `Referer`/`User-Agent` 绕防盗链）。多数无害，但理论上它能看到
经过它的所有播放请求。看到这个标记不用慌，知道就行。

**扫描的边界**：只拆文件、读字符串，**不执行代码**。所以能挡"明着写"的恶意行为，
挡不住刻意混淆的、运行时加载的、藏在 `.so` 里的。别把它当安全沙箱。

## 直播

直播源分三档：

| 档位 | 含义 |
|---|---|
| 优选 | 参与常规解析和测活，默认 10 个 |
| 备选 | 只做初筛（数频道），不参与解析。价值超过优选末位时自动顶上去 |
| 屏蔽 | 不解析、不输出，但保留记录 |

**大聚合 / 小聚合**

| | 频率 | 做什么 |
|---|---|---|
| 大聚合 | 3 天 | 重新展开优选源的 TXT/M3U，看频道增减 |
| 小聚合 | 1 天 | 用上次的频道清单，只测线路 |
| 备选初筛 | 2 天 | 只解析备选的频道数，决定要不要补位 |

手册上还有四个按钮可以随时手动触发。

**线路排序规则**

```
分片取不到（内网地址/超时）→ 排最后且默认不输出
码率过低（<200kbps，多半黑屏）→ 排最后
然后：分辨率高的优先 → 延迟低的优先
```

每个台输出 5 条（设置项 `live_lines_per`）。

**分组**：央视（按号码）→ 卫视（按线路数）→ IPV6央视（纯 v6 线路）。

**屏蔽/删除**是有记忆的：15 天后复检一次，通了就回备选；连续 5 次不通才真删。
原接口以后又带回同一个地址的话，按新源处理（进备选，重新解析一次）。

## 输出

| 档位 | 适合谁 |
|---|---|
| 默认档 | 大多数 TVBox / 影视仓，平衡站点数和体积 |
| 全能档 | 想要最多站点，能接受首屏稍慢 |
| 直连档 | 不想加载任何 jar 的客户端，或排查"是不是插件的问题" |
| LibreTV | 网页版 LibreTV，只吃 CMS |

输出里第一个站点是内置豆瓣（影视墙，响应快，不算站点名额），名字带生成时间，
方便判断电视上用的是不是最新配置。不需要的话在设置里关掉。

## 设置项全表

改完**下一次聚合生效**，不用重启容器。

### 聚合

| 设置 | 默认 | 说明 |
|---|---|---|
| 默认档采集站点上限 | 12 | 主用采集站最多几个 |
| 单配置一次最多并几条 CMS | 40 | 防止一个接口一次灌爆，多轮累积 |
| 采集源池上限 | 120 | 源池最多存多少条 |
| 每轮体检预算 | 40 | 每轮最多探多少个（按最久没探的轮转） |
| 每个站最多几个分类 | 12 | 分类太多电视上翻很久 |
| 主线路数量上限 | 10 | 同时解析几条配置接口 |
| 主站数量下限 | 8 | 少于这个数会从备选里补 |
| 自动补位 | 1 | 主线路不够时自动从备选补 |
| 连续解析出 0 站就下沉 | 2 | 连续几次解析出 0 个站，自动降为备选 |

### 输出

| 设置 | 默认 | 说明 |
|---|---|---|
| 输出排序 | 按资源类型 | 按类型 / 按响应时间 / 按名称 |
| 首个站点用内置豆瓣 | 1 | 关掉则第一个站点是普通采集站 |
| 时间后面的文字 | 豆瓣 | 首站名字：`2026-11-27  13:24  豆瓣` |
| 首个站点名加聚合时间 | 1 | 关掉则首站名不带时间 |
| 默认档/全能档扩展站点数 | 120 | 带多少个 jar/js/py 站点 |
| LibreTV 接口数 | 100 | LibreTV 输出多少个 CMS |
| 输出里带直播 | 1 | 把央视+卫视写进 tvbox.json 的 lives |

### 直播

| 设置 | 默认 | 说明 |
|---|---|---|
| 直播优选源个数 | 10 | 其余做备选 |
| 直播源自动补位 | 1 | 备选价值超过门槛就顶进优选 |
| 直播大聚合间隔 | 3 天 | 重新展开 TXT/M3U |
| 直播小聚合间隔 | 1 天 | 只测线路 |
| 直播备选初筛间隔 | 2 天 | 只解析频道数 |
| 每轮最多测几条线路 | 1500 | 越大越准，越慢 |
| 每个台输出几条线路 | 5 | 客户端里的多线路数量 |
| 分片取不到的线路不输出 | 1 | 关掉则保留但排最后 |
| 屏蔽/删除的源多少天复检 | 15 | |
| 复检连续失败几次就真删 | 5 | |

### 定时

| 设置 | 默认 | 说明 |
|---|---|---|
| 聚合间隔模式 | 每 N 小时 | 或「每天某点」 |
| 扩展资源测速间隔 | 12 小时 | 多久重测一次 jar/js 的可达性 |

## 怎么判断哪里出了问题

**面板「体检报告」**（`/report.md`）是最快的入口，里面有每个站的状态和失败原因。

| 现象 | 先看这里 |
|---|---|
| 站点只有十几个 | 采集站点统计行的「去重」和「合并重复」——可能是源本身重复太多 |
| 电视上点开黑屏 | 直播页的「分片不可达 / 低码率」计数；也可能是线路当前失效，换条线路试试 |
| 配置加载慢 | 全能档站点数太多，降到默认档 |
| 提示"配置信息初始化失败" | 多半是某个插件站点的 `ext` 外链拉不到；切「直连档」对比可确认 |
| 首站一直转圈 | 内置豆瓣需要客户端支持（`csp_Douban`），关掉「首个站点用内置豆瓣」即可 |
| 面板打不开 | 看容器日志；`TOKEN` 没设且监听 0.0.0.0 时是无鉴权状态 |
